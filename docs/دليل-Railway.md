# دليل نشر Railway — للمالك (خطوات دقيقة)

النسخة السحابية الدائمة (تعمل 24/7 من أي مكان). **نفس كود GitHub** تماماً؛
الفرق الوحيد: `DATA_DIR=/data` والبيانات على قرص Railway الدائم (Volume).

> أُصلحت مشكلتان رصدهما الفحص: (1) **انجراف النسخ** — ثُبّتت النسخ في
> `requirements.txt` فيطابق رندر Railway المحلي. (2) **القاعدة الفارغة** — تُعالَج
> بخطوات الـVolume أدناه.

---

## المتطلّب المسبق (يقوم به المطوّر)
دمج فرع `p6-deploy-prep` في الفرع الرئيسي ودفعه إلى GitHub. *(ينتظر إذنك المباشر.)*

---

## الخطوة 1 — اربط Railway بالمستودع
1. ادخل [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo**.
2. اختر `nwtsrash-lgtm/mahwous-pricing-v2`.
3. سيكتشف Railway الإعداد تلقائياً عبر `Procfile`.

## الخطوة 2 — أنشئ القرص الدائم (Volume)
1. داخل المشروع → الخدمة → **Settings → Volumes → New Volume**.
2. **Mount Path:** اكتب بالضبط: `/data`
3. الحجم: **1 GB** (القاعدة 263MB + الكاشات ≈25MB + هامش).

## الخطوة 3 — اضبط المتغيّرات والأسرار (Variables)
في تبويب **Variables** أضِف:

| المفتاح | القيمة | إلزامي؟ |
|---|---|---|
| `DATA_DIR` | `/data` | **نعم** — يوجّه التطبيق للقرص الدائم |
| `GEMINI_API_KEYS` | `["مفتاحك"]` | لا — فقط لتفعيل الذكاء الاصطناعي لاحقاً |
| `OPENROUTER_API_KEY` | `مفتاحك` | لا |
| `WEBHOOK_UPDATE_PRICES` | `رابط Make` | لا — للإرسال لاحقاً بإذنك المباشر |

> 🔒 الأسرار تُكتب **هنا فقط** (لوحة Railway) — لا في أي ملف ولا في GitHub.

## الخطوة 4 — ارفع البيانات إلى الـVolume (مرة واحدة)
الملفات الثلاثة من مجلد `data` المحلي:
- `pricing_v18.db` (≈263MB) · `missing_cache.json` (≈11MB) · **`pricing_cache.json` (≈14MB)**

> ⚠️ **شحن `pricing_cache.json` مهم جداً:** بدونه أول تحليل يبني الفهرس ~22–30 دقيقة
> وقد يُنهيه Railway (timeout/إعادة تشغيل). **معه أول فتح فوري.**

الرفع يحتاج وصول المالك عبر أداة Railway (لا يمكن سحب 263MB من اللوحة):
```
# على جهاز المطوّر (مرة واحدة):
npm i -g @railway/cli      # أو حمّل railway CLI
railway login
railway link               # اختر المشروع والخدمة
# انسخ الملفات الثلاثة إلى الـVolume المركّب على /data:
railway run cp ./data/pricing_v18.db    /data/pricing_v18.db
railway run cp ./data/missing_cache.json /data/missing_cache.json
railway run cp ./data/pricing_cache.json /data/pricing_cache.json
# تحقّق:
railway run ls -lh /data
```
> ملاحظة: الأوامر أعلاه تنفّذ النسخ داخل بيئة Railway حيث الـVolume مركّب على `/data`.
> إن كانت الملفات على جهاز المطوّر، استخدم طريقة الرفع التي تدعمها نسختك من الأداة
> (أو ارفعها إلى تخزين مؤقّت ثم `railway run` لتنزيلها إلى `/data`). الهدف النهائي:
> وجود الملفات الثلاثة داخل `/data` على الـVolume.

## الخطوة 5 — انشر وتحقّق
1. Railway يبني تلقائياً (يثبّت النسخ المثبّتة → رندر مطابق للمحلي).
2. افتح الرابط العام → لوحة التحكم.
3. ارفع كتالوجك → **«🚀 ابدأ التحليل»** → نتائج **فورية** (الكاش دافئ) + البانر الأخضر
   والأرقام (🔴 3516 / 🟢 859 / ✅ 897 / 🔍 6062 …).

---

## تأكيدات أمان
- خطّاف التحميل التلقائي **مُزال** — الإنتاج بالرفع اليدوي فقط.
- `use_ai=False` افتراضياً (لا تكلفة، لا مفاتيح مطلوبة للمسار الأساسي).
- لا إرسال لـ Make ولا كتابة في القاعدة.
- `competitors_list_v30.json` يأتي مع المستودع (مُتعقَّب)؛ بقية `data/` على الـVolume.

## تحديث البيانات لاحقاً
- لتحديث القاعدة/الكاشات: كرّر الخطوة 4 (انسخ الملف المحدَّث إلى `/data`).
- لتحديث الكود: ادفع إلى GitHub → Railway يعيد النشر تلقائياً (البيانات على الـVolume لا تتأثّر).
