## 1 — الرؤية والأهداف: «عين السوق»

تحويل مهووس من أداة تسعير تُقرأ إلى **عينٍ على السوق تُدار بها القرارات**:

| المحور | الوضع الموثَّق اليوم | الهدف الرقمي |
|---|---|---|
| تغطية السوق | 280,292 منتج منافس / 24 متجراً مكشوطاً (CHANGELOG) | **500,000 منتج** مع توسيع المتاجر عبر `discovered_stores` القائم |
| الكتالوج | 11,565 منتجاً | جاهزية معمارية لـ**20,000** بلا تدهور أداء |
| بيانات لا تكذب | حارس نضارة جزئي (`STALE_AFTER_DAYS=3` في `services/opportunity_service.py`) | **100%** من اقتراحات الأسعار موسومة بعمر بياناتها؛ تاريخ الأسعار **و**التقييمات محفوظ إلحاقياً للأبد |
| ذكاء مؤرَّض | AI للمطابقة/التوجيه لا للسعر (`services/ai_service.py:4`) | **صفر** نصّ مُختلَق: كل نوتة/مواصفة تحمل مصدرها أو لا تُكتب |
| الأداء | فتح الرادار من كاش مُسبق (39s→فوري، موثَّق) | فتح أي صفحة بقراءة مفهرسة **≤150ms** (وسيط 3 قياسات معزولة) |

**تعريف العبقرية الحاكم لكل بند أدناه:** أكبر أثر بأصغر تغيير صحيح، مُثبَت بالدليل، وقابل للتراجع.
المتجر حيّ — الجرّاح يُعرف بأن مريضه يستيقظ سليماً في كل مرة، لا بسرعة مشرطه.

## 3 — الحوكمة غير القابلة للتفاوض (تسري على كل وحدة عمل أدناه)

1. **الذكاء مؤرَّض حصراً:** ممنوع اختراع نوتات/مواصفات/أرقام؛ كل مخرَج AI يحمل مصدره المؤرَّض أو يُرفض.
2. **الأسرار من `.env` / `.streamlit/secrets.toml` فقط** — لا سرّ في كود ولا وثيقة ولا commit، أبداً.
3. **`verify=False` ممنوع نهائياً** في أي نداء شبكة.
4. **جداول الأرشيف إلحاقٌ فقط للأبد:** `price_history` (القرارات عبر `append_price_decision`
   حصراً — `utils/db_manager.py:602`)، `events`، و`rating_history` القادم. لا UPDATE/DELETE عليها إطلاقاً.
   (`upsert_price_history` — `utils/db_manager.py:540` — لتاريخ السوق فقط، محظور على القرارات.)
5. **كل قراءة تشخيصية `mode=ro`** — الكتابة تفشل على مستوى SQLite.
6. **لا إرسال حيّ أبداً دون dry-run يراجعه المالك.** أي مساس بالتسعير/التصدير يمرّ بوضع الظل أولاً.
7. **جراحيّ:** >~30 سطراً أو حذف ميزة ⇒ توقّف واستئذان. grep قبل أي حذف شاملاً `tests/`. الحذف بالاسم لا بالسطر.
8. **معاينة `streamlit.testing.v1.AppTest` قبل دمج أي واجهة** (قاعدة CLAUDE.md 9).
9. **بوّابة أداء:** أي بند يلمس مسار فتح صفحة ⇒ قراءة مفهرسة **≤150ms** (وسيط 3 قياسات معزولة)؛
   إعادة البناء الثقيلة توضع **حصراً** في نهاية جولة الكشط (النمط القائم: `scraper_service.py:476-529`).

## 4 — منهجية التنفيذ: تسلسل بوّابات، لا مواعيد

**لا وعود بتواريخ في هذه الوثيقة.** كل وحدة عمل تمرّ بهذا الطقس الثابت:

```
(1) اكتشاف الأرضية حيّاً: pytest كامل + قراءة تليمتري mode=ro ⇒ تثبيت الناتج الخام
(2) فرع + وسم أخضر: git checkout -b <وحدة> && git tag green-pre-<وحدة>   ← مسار التراجع
(3) التنفيذ داخل حدود الوحدة (لا كتلة تمسّ أكثر من 3 ملفات إنتاجية)
(4) البوّابة بعد: pytest أخضر بعددٍ ≥ الأرضية — أي نقص ⇒ تراجع فوري
(5) commit صغير (رسالة عربية عبر git commit -F حصراً — ‏-m متعدد الأسطر أنتج حطاماً سابقاً)
(6) تقرير رقمي من ستة أسطر:
    الفرع: … | الكوميتات: n | البوابة قبل/بعد: X/Y | git diff --stat: … | انحرافات عن المراسي: لا/نص | الشجرة: …
(7) توقف تام — موافقة المالك شرط بدء الوحدة التالية
```

**مؤجَّل صراحةً خارج هذه الخطة (قرار حاكم):** أي تقسيم/إعادة هيكلة لـ`engines/engine.py` أو
`utils/db_manager.py` أو `engines/ai_engine.py` — ملفات حرجة كبيرة، تقسيمها مخاطرة لا يقابلها أثر مالي الآن.
كذلك: وصل `services/pricing_service.py` (قاعدة CLAUDE.md 11) · أي إعادة كتابة واجهة خارج Streamlit
(«لا React» — قرار موثَّق في دفتر التسليم) · أي لمس لـ`#PRESERVED_LOGIC`.
