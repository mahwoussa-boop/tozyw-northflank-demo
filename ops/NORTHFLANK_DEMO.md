# تشغيل Tozyw كتجربة على Northflank

> **تصنيف هذا المسار: تجربة فقط.** لا تنقل قواعد SQLite الحية ولا مفاتيح الذكاء الاصطناعي ولا بيانات المتجر إلى Northflank في هذا الإعداد. تستخدم الحاوية `DATA_DIR=/var/tozyw-demo/data` الذي يبدأ فارغاً مع كل نشر ما لم يُربط Volume؛ ولا يُنشأ Volume أو تُضاف وسيلة دفع ضمن هذا الدليل.

## ما جهزناه في المستودع

| الملف | الوظيفة |
|---|---|
| `Dockerfile` | يبني تطبيق Streamlit على Python 3.11 ويستمع على المنفذ الذي يقدمه Northflank في `PORT`. |
| `.dockerignore` | يستبعد قواعد SQLite وملفات `.env` وأسرار Streamlit ومجلدات الجلسات من build context. |
| `Procfile` | يبقى للتشغيل المحلي والمنصات الأخرى؛ لا تعتمد عليه حاوية Northflank. |

## إعداد الخدمة التجريبية

أنشئ خدمة جديدة من مستودع GitHub الخاص `mahwoussa-boop/tozyw-production` واختر الفرع `main`. اختر بناء **Dockerfile** من جذر المستودع، ثم عيّن منفذ HTTP الخارجي إلى `7860` أو إلى المنفذ الذي تعرضه لوحة الخدمة بعد البناء. لا تفعل autoscaling، واضبط نسخة واحدة فقط.

لا تضف `DATA_DIR` يدويًا في التجربة؛ الصورة تضبطه على مسار تجريبي مستقل. لا تضف `SUPABASE_*` أو `OPENROUTER_*` أو مفاتيح المزودين أو ملفات rclone أو قواعد SQLite كمتغيرات خدمة خلال مرحلة العرض.

## حدود الإطلاق

نجاح التجربة يعني فقط أن الصفحة الرئيسية للتطبيق تعمل من مراجعة `main` وأن التطبيق يتعامل مع غياب البيانات بلطف. لا يعني نجاحاً أن كشط المنافسين أو التحليل أو النسخ الاحتياطي يعمل، ولا يثبت ديمومة أي بيانات.

لتحويله إلى تشغيل بحالة دائمة يلزم قرار منفصل: إضافة وسيلة دفع، إنشاء Volume أحادي القراءة/الكتابة، إبقاء نسخة خدمة واحدة، ترحيل SQLite بطريقة واعية بـWAL، واختبار الاستعادة. عندها لا يعود الحل «نشرًا مجانيًا». [1] [2]

## فحص البناء محلياً

```bash
docker build -t tozyw-demo .
docker run --rm -p 7860:7860 -e PORT=7860 tozyw-demo
```
