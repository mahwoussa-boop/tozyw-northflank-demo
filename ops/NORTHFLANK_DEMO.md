# تشغيل Tozyw كتجربة على Northflank

> **تصنيف هذا المسار: تجربة فقط.** لا تنقل قواعد SQLite الحية ولا مفاتيح الذكاء الاصطناعي ولا بيانات المتجر إلى Northflank في هذا الإعداد. تستخدم الحاوية `DATA_DIR=/var/tozyw-demo/data` الذي يبدأ فارغاً مع كل نشر ما لم يُربط Volume؛ ولا يُنشأ Volume أو تُضاف وسيلة دفع ضمن هذا الدليل.

## ما جهزناه في المستودع

| الملف | الوظيفة |
|---|---|
| `Dockerfile` | يبني تطبيق Streamlit على Python 3.11 ويستمع على المنفذ الذي يقدمه Northflank في `PORT`. |
| `.dockerignore` | يستبعد قواعد SQLite وملفات `.env` وأسرار Streamlit ومجلدات الجلسات من build context. |
| `Procfile` | يبقى للتشغيل المحلي والمنصات الأخرى؛ لا تعتمد عليه حاوية Northflank. |

## إعداد الخدمة التجريبية

أنشئ خدمة جديدة من مستودع GitHub الخاص `mahwoussa-boop/tozyw-production` واختر الفرع `main`. اختر بناء **Dockerfile** من جذر المستودع، ثم عيّن منفذ HTTP الخارجي إلى `7860` أو إلى المنفذ الذي تعرضه لوحة الخدمة بعد البناء. لا تفعل autoscaling، واضبط نسخة واحدة فقط.

لا تضف `DATA_DIR` يدويًا في التجربة؛ الصورة تضبطه على مسار تجريبي مستقل. لا تضف `SUPABASE_*` أو `OPENROUTER_*` أو مفاتيح المزودين أو ملفات rclone أو قواعد SQLite كمتغيرات خدمة خلال مرحلة العرض.

## حدود الإطلاق

نجاح التجربة يعني فقط أن الصفحة الرئيسية للتطبيق تعمل من مراجعة `main` وأن التطبيق يتعامل مع غياب البيانات بلطف. لا يعني نجاحاً أن كشط المنافسين أو التحليل أو النسخ الاحتياطي يعمل، ولا يثبت ديمومة أي بيانات.

لتحويله إلى تشغيل بحالة دائمة يلزم قرار منفصل: إضافة وسيلة دفع، إنشاء Volume أحادي القراءة/الكتابة، إبقاء نسخة خدمة واحدة، ترحيل SQLite بطريقة واعية بـWAL، واختبار الاستعادة. عندها لا يعود الحل «نشرًا مجانيًا». [1] [2]

## فحص البناء محلياً

```bash
docker build -t tozyw-demo .
docker run --rm -p 7860:7860 -e PORT=7860 tozyw-demo
```

## حالة الربط

تم التحقق من وجود جلسة Northflank نشطة للفريق الحالي. يُنشأ مشروع مستقل باسم `tozyw-demo` قبل ربط الخدمة بالمستودع الخاص، مع إبقاء النشر تجريبياً ومن دون Volume أو أسرار إنتاج.

ملاحظة تشغيلية: تم فتح مسار إنشاء المشروع، وكانت الواجهة في حالة اتصال/تحميل؛ لا أُنشئ أي مشروع أو خدمة قبل ظهور النموذج كاملاً والتحقق من إعداداته.

## قيد الحساب المرئي في لوحة Northflank

عند فتح نموذج المشروع ظهر تنبيه بأن الفريق بلغ حد هذا النوع من المشاريع المجانية؛ وتوضح الواجهة أن الحساب يسمح بمشروع مجاني واحد على Northflank Cloud ومشروع واحد على BYOC. لا تُنشأ ترقية ولا تُنشأ خدمة جديدة قبل التحقق من المشاريع القائمة أو موافقة صريحة على أي تكلفة.

## مشروع موجود

تعرض لوحة الفريق مشروعاً مجانياً قائماً باسم `ghk` في منطقة US Central وحالته Created. بما أنه لم يُنشأ في هذه الجلسة، لا يُعاد استخدامه أو تُنشأ خدمة داخله قبل موافقة المالك الصريحة.

## ربط GitHub

تؤكد لوحة التكاملات عدم وجود أي حساب GitHub مرتبط بالفريق. ربط GitHub سيمنح Northflank القدرة على قراءة المستودعات المختارة لبناء الخدمة؛ لذلك لا يُضغط زر التفويض النهائي قبل موافقة المستخدم الصريحة على هذا النطاق.

تم بدء مسار ربط GitHub في Northflank، لكن حساب GitHub لم يظهر بعد ضمن الحسابات المرتبطة. الصفحة تعرض رابط متابعة داخلياً لاختيار حساب GitHub؛ لم تُمنح صلاحية مستودعات حتى هذه اللحظة.

تم ربط حساب GitHub بالفريق بنجاح، لكن قائمة المستودعات المتصلة ما زالت فارغة. يلزم فتح إعداد GitHub App واختيار المستودع `mahwoussa-boop/tozyw-production` فقط؛ لا تُمنح صلاحية جميع المستودعات.

تم فتح خيار تعديل تثبيت GitHub App، لكن الواجهة لم تنتقل إلى صفحة اختيار المستودعات وبقيت قائمة المستودعات فارغة. لا تُنشأ خدمة قبل منح التطبيق وصولاً صريحاً إلى المستودع المستهدف فقط.

تم العثور على تطبيق GitHub المثبت `Northflank Cloud - Build & Run` في إعدادات حساب GitHub. الخطوة التالية هي فتح Configure وقصر نطاق التطبيق على المستودع `mahwoussa-boop/tozyw-production` بدلاً من كل المستودعات.

## نطاق GitHub App

صفحة GitHub تؤكد أن تطبيق Northflank يطلب صلاحيات كتابة على الإدارة والكود وحالات commits والنشرات وpull requests وrepository hooks. يمكن تقييد هذا النطاق على مستودع واحد فقط، لكن لا يمكن تحويله إلى وصول قراءة فقط من هذه الصفحة. يلزم قبول صريح لهذه الصلاحيات قبل اختيار المستودع وحفظ التثبيت.
