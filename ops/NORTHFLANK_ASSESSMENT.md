# تقييم Northflank لتشغيل Tozyw

## الحكم التنفيذي

**لا يُعتمد Northflank كخيار إنتاجي مجاني لـ Tozyw.** تتيح خطة Developer Sandbox تشغيل موارد محدودة لاختبار المنصة، لكن وثائق Northflank نفسها تنص على أنها ليست للاستخدام الإنتاجي، كما تشترط إضافة وسيلة دفع قبل إنشاء أي مورد مهما كانت الخطة. [1]

| معيار Tozyw | Northflank Developer Sandbox | الحكم |
|---|---|---|
| ربط GitHub وبناء Docker | مدعوم ضمن المنصة. [2] | مناسب تقنياً. |
| التشغيل المجاني | خدمة مجانية محدودة ضمن Sandbox؛ ليست للإنتاج. [1] | غير مقبول كخدمة عمل دائمة. |
| SQLite دائم | يتطلب Volume؛ volume أحادي القراءة/الكتابة يقيد الخدمة بنسخة واحدة. [3] | ممكن تقنياً، لكن ليس تكويناً عالي الإتاحة أو مجانياً مضمونا. |
| البطاقة | مطلوبة لكل الحسابات قبل إنشاء الموارد. [1] | يتطلب bootstrap شخصياً. |
| استمرارية البيانات | Volume دائم؛ التخزين والتشغيل في المسارات المدارة يحاسبان حسب الاستخدام. [2] [3] | لا يمكن تسميته مجانياً دائماً. |

## ما لا يُنفذ

لا يُنشأ حساب Northflank ولا تُضاف وسيلة دفع ولا يُربط المستودع ولا تُنشأ خدمة، حتى يؤكد مالك الحساب قبوله للفاتورة المحتملة وحد الاستخدام. لا تُنقل قاعدة SQLite أو أسرار التطبيق إلى Northflank خلال التجربة.

## البديل المعتمد

يبقى Oracle Always Free الأنسب لحالة Tozyw عندما يصبح حساب المستخدم جاهزاً، لأنه يوفر حوسبة وقرصاً دائماً ضمن الحدود المجانية، مع تشغيل وحيد لقاعدة SQLite ونسخ مشفر مستقل. ملفات ذلك موجودة في `ops/`.
